# Лабораторная 3. Пакет модулей для табличных данных

**Максимум:** 10 баллов (база 6 + дополнительные задания сложностью не менее 4).

На базе стандартной библиотеки и прямой работы с файлами реализовать пакет для загрузки, сохранения и манипулирования таблицами. **Нельзя** использовать `pandas`, `polars` и аналогичные табличные библиотеки.

Запуск демонстрации: `python3 3lab/main.py` из корня репозитория. Демонстрация должна загрузить пример данных своего варианта, выполнить несколько операций API и напечатать таблицу.

Вариант: `(номер зачётной книжки % 4) + 1`.

## Чему учимся: циклы по таблице

Таблица — это матрица, как в линейной алгебре или как лист Excel. Строка — наблюдение, столбец — показатель.

Обязательно:

- `print_table`, `get_values`, `set_values` и обход при `load`/`save` пишутся **циклами** по строкам и столбцам;
- нельзя вручную расписывать каждую ячейку и нельзя подключать `pandas`.

Рекурсия в базе не нужна. Она появляется в дополнительном пункте про вложенные структуры (JSON/YAML).

Лекции: [02 — Списки](../lectures/02-spiski-slovari-stroki.pptx), [03 — Циклы](../lectures/03-cikly.pptx).

## Базовое задание (все варианты)

Внутреннее представление таблицы выбирает автор. Допустимы словарь с атрибутами и вложенными списками, собственный класс и т.п.

При определении API максимально полно использовать возможности сигнатур Python (значения по умолчанию, `*args` / `**kwargs`, возврат нескольких значений). Интенсивно проверять аргументы и возбуждать исключения.

### 1. Загрузка и сохранение

Функции `load_table` и `save_table` — в **отдельных модулях** пакета, по одному модулю на формат варианта (см. таблицу ниже).

Дополнительно: `save_table` в **текстовый файл** (только сохранение), содержимое совпадает с выводом `print_table()`.

### 2. Операции над таблицами

Модуль с базовыми операциями:

- `get_rows_by_number(start, [stop], copy_table=False)` — одна строка или полуинтервал строк по номеру. При `copy_table=False` возвращается представление, через которое изменения видны в исходной таблице; при `copy_table=True` — независимая копия.
- `get_rows_by_index(val1, …, copy_table=False)` — строки, у которых значение **первого столбца** совпадает с одним из `val1`, …, `valN`. Смысл `copy_table` тот же.
- `get_column_types(by_number=True)` — словарь «столбец → тип». Типы: `int`, `float`, `bool`, `str` (по умолчанию `str`). `by_number` выбирает ключ: индекс столбца или его имя.
- `set_column_types(types_dict, by_number=True)` — задать типы столбцов.
- `get_values(column=0)` — список типизированных значений столбца по номеру или по имени.
- `get_value(column=0)` — одно значение для таблицы из одной строки.
- `set_values(values, column=0)` — записать список значений в столбец.
- `set_value(value, column=0)` — одно значение для таблицы из одной строки.
- `print_table()` — печать таблицы в консоль.

### 3. Исключения

У **каждой** публичной функции — не менее одного осмысленного вида исключения (неверный путь, несовпадение числа столбцов, неверный тип, выход за границы, пустая таблица для `get_value` и т.п.).

## Варианты: сюжет и форматы

Первый столбец во всех вариантах — логический ключ строки (имя, артикул, код группы, идентификатор события).

### Вариант 1. Журнал посещаемости — CSV и JSON

Столбцы-пример: `student`, `group`, `date`, `present`, `minutes_late`.

- модуль CSV: `load_table` / `save_table` (разделитель `,`, первая строка — заголовки);
- модуль JSON: таблица как объект `{"columns": [...], "rows": [[...], ...]}`.

Пример фрагмента CSV:

```csv
student,group,date,present,minutes_late
Иванов,ПМ26-1,2026-09-10,true,0
Петрова,ПМ26-1,2026-09-10,false,0
```

### Вариант 2. Склад — TSV и pickle

Столбцы-пример: `sku`, `name`, `qty`, `price`, `reserved`.

- модуль TSV: `load_table` / `save_table` (разделитель табуляция, первая строка — заголовки);
- модуль pickle: сериализация внутреннего представления, удобного автору.

Пример фрагмента TSV:

```
sku	name	qty	price	reserved
A-100	тетрадь	30	45.5	false
B-204	ручка	120	12.0	true
```

### Вариант 3. Расписание пар — Markdown-таблица и YAML

Столбцы-пример: `group`, `weekday`, `pair`, `subject`, `room`.

- модуль Markdown: `load_table` / `save_table` для таблиц вида:

```markdown
| group | weekday | pair | subject | room |
| --- | --- | --- | --- | --- |
| ПМ26-1 | пн | 1 | алгебра | 301 |
| ПМ26-1 | пн | 2 | практикум | 214 |
```

- модуль YAML: список записей-словарей либо объект с `columns` и `rows`. Допускается `PyYAML` (указать в `requirements.txt`).

### Вариант 4. Лента событий — JSON Lines и текстовый дамп

Столбцы-пример: `id`, `ts`, `level`, `source`, `message`.

- модуль JSONL: каждая строка файла — JSON-массив значений **или** JSON-объект одной записи; первая строка-заголовок не используется, имена столбцов берутся из ключей первой записи либо из параметра `columns`;
- текстовый дамп: только `save_table`, формат совпадает с `print_table()`.

Дополнительно к общему требованию текстового дампа вариант 4 уже содержит его как второй формат; тогда третий модуль не нужен — достаточно JSONL + текстового `save_table`.

Пример JSONL:

```json
{"id": "e1", "ts": "2026-09-10T12:00:00", "level": "INFO", "source": "auth", "message": "login"}
{"id": "e2", "ts": "2026-09-10T12:01:10", "level": "ERROR", "source": "db", "message": "timeout"}
```

## Дополнительные задания

Нужно набрать суммарную сложность **не менее 4**. Пункты общие для всех вариантов.

1. `load_table(file1, …)` — сборка таблицы из нескольких файлов того же формата. При несовпадении столбцов — исключение.  
   **сложность 1**

2. Расширение пункта 1. `save_table(..., max_rows=N)` — нарезка на несколько файлов. Полученные файлы читаются `load_table` из пункта 1.  
   **сложность 1**

3. `concat(table1, table2)` и `split(row_number)` — склеить две таблицы / разрезать одну по номеру строки.  
   **сложность 1**

4. Автоопределение типов столбцов по значениям; оформить отдельной функцией и как опцию `load_table`.  
   **сложность 1 или 2** (2 — если корректно разбираются смешанные столбцы и пустые ячейки)

5. Тип «дата и время» на основе модуля `datetime` (для вариантов 1 и 4 — естественное место; для 2 и 3 можно добавить столбец `updated` / `starts_at`).  
   **сложность 1 или 2**

6. Функции `add`, `sub`, `mul`, `div` для столбцов `int`, `float`, `bool`. Продумать сигнатуру и присваивание результата. Некорректные значения — исключения.  
   **сложность 2**

7. Сравнения `eq`, `gr`, `ls`, `ge`, `le`, `ne` — списки булевых значений по строкам; `filter_rows(bool_list, copy_table=False)`.  
   **сложность 3**

8. `merge_tables(table1, table2, by_number=True)` — объединение столбцов, строки сопоставляются по номеру или по первому столбцу. Описать конфликтные ситуации и реакцию на них.  
   **сложность 2**

9. Полноценная поддержка `None` в пустых ячейках: загрузка, операции, `get` / `set`.  
   **сложность 1 или 2**

10. Рекурсивный обход вложенной структуры (словарь/список в духе JSON): функция вызывает себя для вложенного значения и пишет в журнал глубину, ключ и значение. Для вариантов 3–4 это естественное продолжение YAML/JSONL; для 1–2 можно обойти произвольный вложенный JSON-отчёт.  
    **сложность 2**
